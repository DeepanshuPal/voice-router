How the numbers are made

Every figure on the leaderboard comes out of a harness run on real audio. Nothing is hand-edited.

metrics

What we measure

MetricDefinition
WERWord error rate against a reference transcript (edit distance on word sequences). CER for character-based languages is on the roadmap.
p50 latencyMedian wall-clock time per transcription call, in milliseconds.
Cost/minEffective USD per audio minute, from the provider's metered pricing over the audio actually processed.
Score1 - WER when reference transcripts exist, otherwise inverse latency. This is the score the router's benchmark strategy routes on.

harness

How samples are run

Samples are short .wav clips per language in benchmarks/samples/, with same-named reference transcripts in benchmarks/references/. The harness (benchmarks/harness.py) sends every sample to every provider that supports the language, in the same process, back to back:

python -m benchmarks.harness --samples benchmarks/samples \
    --references benchmarks/references --language en

Results land in benchmarks/results.json; this site is regenerated from that file. Nothing is hand-edited: if a number is on the leaderboard, it came out of a harness run.

audio

Where the audio comes from

The current sample set is real human speech from Google's public FLEURS evaluation corpus (CC-BY-4.0) - 15 test-split clips per language for English (en_us), Spanish (es_419), Hindi (hi_in), French (fr_fr), German (de_de), and Japanese (ja_jp), normalized to 16 kHz mono PCM. Clips are 4-14 seconds long, picked at even intervals across the test split for speaker diversity. Reference transcripts are FLEURS' normalized transcriptions. No synthetic or TTS-generated audio is used. Clips and references are committed in benchmarks/samples/ and benchmarks/references/ so anyone can rerun the exact matrix.

cadence

Refresh cadence

A GitHub Action regenerates the site on every push that touches benchmarks/ and on a weekly schedule, because provider quality drifts. Anyone can reproduce the numbers: clone the repo, add provider keys, run the harness.

honesty

Sample data policy

Before the first real multi-provider run, the site renders benchmarks/sample_results.json - synthetic numbers that exist only to demonstrate the format. Sample data is always shown behind a visible SAMPLE DATA banner and is never presented as a real measurement. The moment a real run lands in benchmarks/results.json, it replaces the sample data automatically.

voice-router

Open-source router for voice AI. Benchmarks STT providers per language on accuracy, latency and cost, then routes calls to the best one. Built on LiteLLM and Pipecat.
